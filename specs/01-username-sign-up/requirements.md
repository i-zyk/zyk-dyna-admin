# R01 用户名 + 邮箱注册

> 来源：docs/需求.md 第 3 节「R1 注册」、第 4 节「技术方案约束 / 认证、UI」、第 5 节「非功能需求」

## 背景与目标

现有注册只收集昵称、邮箱和密码。本需求在 Better Auth 中启用 `username` 插件，让用户注册时填写用户名、邮箱和密码（含确认密码），为 R02 的「用户名或邮箱登录」打基础。注册成功后自动登录并进入 `/dashboard`。

本需求同时承担全局非功能要求的落地起点：密码只由 Better Auth 哈希存储、表单可访问性、亮暗主题和窄屏适配，以及项目测试基础设施的搭建。

## 用户故事

- 作为新用户，我希望用用户名、邮箱和密码注册，以便之后用用户名或邮箱登录。
- 作为新用户，我希望在提交前就看到哪一项填错了，以便快速改正。
- 作为新用户，我希望注册成功后直接进入系统，而不用再登录一次。

## 验收标准

- [✅] R01-AC1：当用户名不合法（少于 3 位或多于 30 位、包含字母 / 数字 / `_` / `.` 以外的字符，例如 `ab`、`a b`、`中文名`）时，系统应当在用户名输入框下方显示原因，并且无法提交。
- [✅] R01-AC2：当邮箱格式不合法（例如 `abc`、`a@b`）时，系统应当在邮箱输入框下方显示原因，并且无法提交。
- [✅] R01-AC3：当密码不在 8–128 位之间，或确认密码与密码不一致时，系统应当在对应输入框下方显示原因，并且无法提交。
- [✅] R01-AC4：当用户名已被占用（包括只是大小写不同，例如已有 `tom` 时注册 `Tom`）时，系统应当提示「用户名已存在」。
- [✅] R01-AC5：当邮箱已被注册（包括只是大小写不同）时，系统应当提示「邮箱已被注册」。
- [✅] R01-AC6：当注册请求进行中时，提交按钮应当显示加载状态并处于禁用状态，不能重复提交。
- [✅] R01-AC7：当注册成功时，系统应当自动登录并跳转到 `/dashboard`；刷新页面后仍保持登录状态。
- [✅] R01-AC8：注册成功后，数据库 `user` 表中 `username` 以小写存储、`displayUsername` 保留用户输入的原样大小写、`name` 等于用户名；密码只以 Better Auth 的哈希形式存在 `account.password`，不在任何日志中出现明文。
- [✅] R01-AC9：`/login` 页面可以在「登录 / 注册」之间切换；注册表单每个输入框都有对应的 `<label>`，只用键盘就能完成注册。
- [✅] R01-AC10：`/login` 页面在亮色 / 暗色主题下都正常显示，在 375px 宽的屏幕上不出现横向滚动。
- [✅] R01-AC11：本需求的改动通过 `pnpm run check` 和 `pnpm run check-types`。

## 不在范围内

- 邮箱验证、找回 / 重置密码（不开启 `requireEmailVerification`）
- 第三方登录（GitHub OAuth 等）
- 修改用户名、邮箱或密码，个人资料编辑
- 移动端（`apps/native`）适配
- 用户名可用性的实时远程检查（`isUsernameAvailable`）：PRD 只要求提交后提示「用户名已存在」
