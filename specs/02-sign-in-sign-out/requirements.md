# R02 用户名或邮箱登录 / 退出登录

> 来源：docs/需求.md 第 3 节「R2 登录 / 退出」、第 2 节「范围」（未登录访问受保护页面跳转登录页）、第 4 节「技术方案约束 / 认证」、第 5 节「非功能需求」

## 背景与目标

R01 让用户有了用户名。本需求让用户可以用「用户名或邮箱」加密码登录，统一错误提示，不泄露账号是否存在；并完善登录态下的页面跳转和顶部导航的用户菜单（显示用户名、邮箱和「退出登录」）。

## 用户故事

- 作为已注册用户，我希望输入用户名或邮箱中的任意一个加密码就能登录，以便不用记住注册时用的是哪个。
- 作为已注册用户，我希望登录失败时只看到一句统一的提示，以便账号信息不被他人试探。
- 作为已登录用户，我希望在顶部导航看到自己的用户名和邮箱，并能一键退出登录。

## 验收标准

- [ ] R02-AC1：当输入用户名（大小写与注册时不同也可以）和正确密码时，系统应当登录成功并跳转到 `/dashboard`。
- [ ] R02-AC2：当输入邮箱（大小写与注册时不同也可以）和正确密码时，系统应当登录成功并跳转到 `/dashboard`。
- [ ] R02-AC3：当输入中包含 `@` 时，系统应当按邮箱登录（调用 `signIn.email`），否则按用户名登录（调用 `signIn.username`）。
- [ ] R02-AC4：当密码错误、账号不存在或账号格式不合法时，系统应当统一提示「账号或密码错误」，不透露具体是哪一项错。
- [ ] R02-AC5：当「用户名或邮箱」或「密码」为空时，系统应当在对应输入框下方提示，并且无法提交；登录请求进行中时提交按钮显示加载状态并禁用。
- [ ] R02-AC6：当已登录用户访问 `/login` 时，系统应当直接重定向到 `/dashboard`。
- [ ] R02-AC7：当未登录（包括退出登录后）访问 `/dashboard` 时，系统应当重定向到 `/login`。
- [ ] R02-AC8：已登录时，顶部导航的用户菜单应当显示当前用户名和邮箱，并提供「退出登录」；点击后退出登录并回到 `/login`。
- [ ] R02-AC9：登录表单每个输入框都有对应的 `<label>`，只用键盘就能完成登录和退出登录；`/login` 和顶部导航在亮色 / 暗色主题下正常显示，375px 宽度下不出现横向滚动。
- [ ] R02-AC10：本需求的改动通过 `pnpm run check` 和 `pnpm run check-types`。

## 不在范围内

- 找回 / 重置密码、「记住我」选项
- 第三方登录
- 登录失败次数限制、验证码（Better Auth 自带的速率限制保持默认）
- 移动端（`apps/native`）适配

## 依赖

- 依赖 R01 用户名 + 邮箱注册（username 插件、`usernameClient()`、`auth-validation.ts`、`auth-errors.ts`、测试基础设施）

## 已确认事项（2026-11-06）

- **用户菜单显示的用户名**：显示 `displayUsername`，为空时回退到 `username`，再回退到 `name`。
