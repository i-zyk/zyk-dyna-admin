# R04 人员管理（入库、修改、删除）

> 来源：docs/需求.md 第 2 节「范围」、第 3 节「R4 人员管理（入库、修改、删除）」、第 4 节「技术方案约束 / 人员管理」、第 5 节「非功能需求」（第二期新增，2026-11-07）

## 背景与目标

第二期新增独立的「人员」业务数据：登录用户可以在 Web 管理端新增（入库）、查询、修改、删除人员。人员与登录账号（`user` 表）没有关联；所有登录用户都可以管理全部人员，本期不区分角色权限。删除为物理删除。

## 用户故事

- 作为已登录用户，我希望把一个人员的姓名、工号、联系方式、部门、职位和在职状态录入系统，以便统一管理人员信息。
- 作为已登录用户，我希望按姓名或工号搜索、按状态筛选并分页浏览人员，以便快速找到目标人员。
- 作为已登录用户，我希望修改人员信息，并在工号重复时得到明确提示，以便保证工号唯一。
- 作为已登录用户，我希望删除人员前先确认一次，以便避免误删。
- 作为已登录用户，我希望在别人已经删除某个人员后，我再去编辑或删除它时得到清楚的提示，而不是页面崩溃。

## 验收标准

- [ ] R04-AC1：未登录访问 `/persons`、`/persons/new`、`/persons/<任意 id>/edit` 时，系统应当重定向到 `/login`；未登录调用 `person.list`、`person.getById`、`person.create`、`person.update`、`person.delete` 时，系统应当返回 `UNAUTHORIZED`。
- [ ] R04-AC2：顶部导航有「人员管理」入口，进入 `/persons`；列表页有「新增人员」按钮进入 `/persons/new`；列表每行有「编辑」按钮进入 `/persons/<id>/edit`。
- [ ] R04-AC3：当只填写必填项（姓名、工号；状态默认「在职」）并提交时，系统应当新增成功，toast 提示「已保存」，回到列表页，新人员出现在列表第一行；选填项留空时存为 `null`（不存空字符串），列表对应列显示 `-`。
- [ ] R04-AC4：当姓名为空或只有空格、姓名去掉首尾空格后超过 50 个字符、工号不是 2–32 位或含字母数字和 `-` 以外的字符（如中文、空格）、手机号不是 `1` 开头且第二位 3–9 的 11 位数字、邮箱格式不正确、部门或职位超过 50 个字符、备注超过 500 个字符时，系统应当无法提交，并在对应字段下方显示原因。
- [ ] R04-AC5：工号统一转大写存储且全局唯一；当新增时使用已存在的工号，或编辑时把工号改成别人已有的工号（包括只是大小写不同，如 `a001` 与 `A001`）时，系统应当在工号字段下方提示「工号已存在」，服务端返回 `CONFLICT`。
- [ ] R04-AC6：服务端不信任前端，统一做 trim、工号转大写、邮箱转小写、选填字段空字符串转 `null`，并用 Zod 再校验一次；入参不合法时返回 `BAD_REQUEST`。
- [ ] R04-AC7：编辑页打开时回填当前数据；修改后保存，toast 提示「已保存」，回到列表页显示修改后的数据，更新时间随之变化；点击「取消」回到列表页，不保存任何修改。
- [ ] R04-AC8：表单提交中，提交按钮显示加载状态并禁止重复提交。
- [ ] R04-AC9：列表表格列为工号、姓名、部门、职位、手机号、状态、更新时间、操作（编辑 / 删除）；按更新时间倒序，每页 20 条，提供「上一页」/「下一页」和「第 X / Y 页，共 N 条」；更新时间格式为 `YYYY-MM-DD HH:mm`；空字段显示 `-`，页面任何位置都不出现 `null` / `undefined`；超过 20 条时可以翻页。
- [ ] R04-AC10：搜索框按姓名或工号的一部分模糊搜索（不区分大小写），按回车或点击「搜索」生效，搜索后回到第 1 页；状态可筛选「全部 / 在职 / 离职」，筛选后回到第 1 页。
- [ ] R04-AC11：没有任何人员时显示空状态「暂无人员」，并提供「新增人员」入口；有搜索词或状态筛选但无结果时显示「没有找到匹配的人员」。
- [ ] R04-AC12：点击「删除」弹出确认对话框「确定删除人员「姓名（工号）」吗？删除后无法恢复。」；点击取消（或按 Esc）不删除；确认后物理删除该人员，toast 提示「已删除」并刷新列表，刷新页面后也不存在；当前页被删空时自动回到上一页。
- [ ] R04-AC13：当编辑或删除一个已被删除的人员时（打开编辑页、提交编辑、确认删除），系统应当提示「该人员不存在或已被删除」：编辑页显示该提示并提供返回列表的入口，删除时 toast 提示并刷新列表；页面不崩溃；服务端返回 `NOT_FOUND`。
- [ ] R04-AC14：后端在 `packages/api/src/routers/` 新增 `person` 子路由并合并进 `appRouter`，全部使用 `protectedProcedure`、入参用 Zod 校验：`person.list({ keyword?, status?, page, pageSize })` 返回 `{ items, total, page, pageSize }`，`pageSize` 上限 100；另有 `person.getById({ id })`、`person.create(input)`、`person.update({ id, ...input })`、`person.delete({ id })`。
- [ ] R04-AC15：数据表在 `packages/db/prisma/schema/person.prisma` 定义模型 `Person`（`@@map("person")`），`id` 为 cuid，`employeeNo` 唯一，状态为 `enum PersonStatus { ACTIVE INACTIVE }`，`createdAt` / `updatedAt` 自动维护，`updatedAt` 有索引；迁移名 `add_person`；E2E 的 `global-setup` 清空业务表时包含 `person` 表。
- [ ] R04-AC16：列表、搜索、筛选、翻页、表单、确认对话框只用键盘就能完成操作，表单输入框都有对应的 `<label>`；在亮色 / 暗色主题下正常显示；在 375px 宽的屏幕上不出现页面级横向滚动（表格可以在自身容器内横向滚动）。
- [ ] R04-AC17：本需求的改动通过 `pnpm run check` 和 `pnpm run check-types`。

## 不在范围内

- 人员批量导入 / 导出
- 操作日志
- 角色权限（所有登录用户都可管理全部人员）
- 软删除与回收站（本期物理删除）
- 人员与登录账号（`user` 表）关联
- 列表搜索条件、页码同步到 URL
- 移动端（`apps/native`）适配

## 依赖

- 依赖 R01 用户名 + 邮箱注册（测试基础设施：Vitest、Playwright、测试库 `zyk_dyna_admin_test`、`global-setup`）
- 依赖 R02 用户名或邮箱登录 / 退出登录（服务端 session 校验与登录重定向、顶部导航，E2E 需要先登录）
